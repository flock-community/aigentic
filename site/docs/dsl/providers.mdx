# Providers

Aigentic provides a consistent interface for working with different Large Language Model (LLM) providers. This allows you to easily switch between models or use multiple models in your application.

## Supported Models

Aigentic supports several LLM providers out of the box:

## Thinking configuration

Reasoning models let you control how much they think before answering. Aigentic exposes this through two `generationConfig` DSL functions: `thinkingBudget(tokens)` and `thinkingLevel(level)`. They are mutually exclusive; configuring both throws an `AigenticException`. Leaving both unset uses the model's default behaviour.

Model/identifier and thinking-level errors (an unsupported combination, or a level that isn't allowed on that model) are raised client-side as soon as the model is built — for example inside `geminiModel { ... }`, before any request is ever sent — not later when the agent runs.

<Tabs>
  <TabItem value="Gemini" label="Gemini">
    <CodeBlock language="kotlin">
      {`import community.flock.aigentic.core.model.ThinkingLevel

agent<String, Answer> {
    geminiModel {
        apiKey("your-api-key")
        modelIdentifier(GeminiModelIdentifier.Gemini3_5Flash)
        generationConfig {
            thinkingLevel(ThinkingLevel.LOW)
        }
    }
    // ...
}`}
    </CodeBlock>

    Gemini 2.x models only support `thinkingBudget()` (a token budget, `-1` for dynamic, `0` to disable except on Pro). Gemini 3.x models only support `thinkingLevel()`.

    | Model | Default level | Supported levels |
    | --- | --- | --- |
    | `gemini-2.5-pro` / `gemini-2.5-flash` / `gemini-2.5-flash-lite` | n/a | `thinkingBudget` only |
    | `gemini-3.7-flash` | medium | LOW, MEDIUM, HIGH (MINIMAL maps to LOW) |
    | `gemini-3.6-flash` | medium | MINIMAL, LOW, MEDIUM, HIGH |
    | `gemini-3.5-flash` | medium | MINIMAL, LOW, MEDIUM, HIGH |
    | `gemini-3.5-flash-lite` | minimal | MINIMAL, LOW, MEDIUM, HIGH |
    | `gemini-3.1-pro-preview` | high | LOW, MEDIUM, HIGH (MINIMAL maps to LOW) |
    | `gemini-3.1-flash-lite` | minimal | MINIMAL, LOW, MEDIUM, HIGH |
    | `gemini-3-flash-preview` | high | MINIMAL, LOW, MEDIUM, HIGH |

    `ThinkingLevel` is an aigentic-level concept; each provider maps it to what the underlying model supports. `MINIMAL` maps to the lowest level the model supports: `low` on `gemini-3.7-flash` and `gemini-3.1-pro-preview`, since those two models don't have a MINIMAL level of their own.

    For a `Custom(identifier)` model identifier, Aigentic infers the same rules from the identifier prefix: an identifier starting with `"gemini-2"` only supports `thinkingBudget()` (a `thinkingLevel()` throws), one starting with `"gemini-3"` only supports `thinkingLevel()` with all four levels (a `thinkingBudget()` throws). Any other identifier (a tuned endpoint, a proxy name, or an older model like `gemini-1.5-pro`) is passed through without validation — both `thinkingBudget()` and `thinkingLevel()` are accepted as-is.
  </TabItem>

  <TabItem value="OpenAI" label="OpenAI">
    <CodeBlock language="kotlin">
      {`import community.flock.aigentic.core.model.ThinkingLevel

agent<String, Answer> {
    openAIModel {
        apiKey("your-api-key")
        modelIdentifier(OpenAIModelIdentifier.O3)
        generationConfig {
            thinkingLevel(ThinkingLevel.LOW)
        }
    }
    // ...
}`}
    </CodeBlock>

    `thinkingLevel()` maps to OpenAI's `reasoning_effort` request field and is only supported on reasoning models (the `o`-series, the `gpt-5` family, and any `Custom` model identifier). Configuring it on a non-reasoning model, or configuring `thinkingBudget()` on any OpenAI model, throws an exception.

    `MINIMAL` maps to the lowest level the model supports: on the `gpt-5` family and `Custom` model identifiers it is passed through as `minimal`, while on the `o`-series models (`o1`, `o3`, `o3-mini`, `o4-mini`, or their pro variants), which don't have a MINIMAL reasoning_effort of their own, it maps to `low`.
  </TabItem>

## Structured output (Gemini & Vertex AI)

You don’t need structured output to use output types. With any provider you can define `agent<Input, Output>` and Aigentic will parse the model’s response into your `Output` type in the normal chat/tool‑calling flow.

Structured output is an optional mode for Gemini and Vertex AI that uses the provider’s native JSON schema support. Aigentic will use it automatically when:

- You specify an output type on your agent (e.g., `agent<Input, Output>`), and
- You don’t add any tools to the agent

Why use it
- Handles complex, deeply nested objects more reliably

When not to use it
- You need tools (structured output can’t run tools as a Gemini limitation)
- Your output is simple enough for the normal flow

Troubleshooting
- If you see Gemini errors like `MALFORMED_FUNCTION_CALL`, try removing tools and rely on structured output by specifying an output type.

```kotlin
@AigenticParameter
data class Summary(val title: String, val bullets: List<String>)

val vertexAgent = agent<String, Summary> {
    vertexAIModel {
        project("your-project-id")
        location("your-location")
        modelIdentifier(VertexAIModelIdentifier.Gemini2_5Flash)
    }
    task("Summarize the text as title + bullets") {
        addInstruction("Return a title and bullet points")
    }
    // No tools added → structured output request
}
```

## Bring your own model

All model implementations in Aigentic implement the `Model` interface, which defines the contract for interacting with LLM providers:

```kotlin
interface Model {
    val modelIdentifier: ModelIdentifier
    val generationSettings: GenerationSettings

    suspend fun sendRequest(
        messages: List<Message>,
        tools: List<ToolDescription>,
        structuredOutputParameter: Parameter?,
    ): ModelResponse
}
```

You can implement this interface to connect to your own model
